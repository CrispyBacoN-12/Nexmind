## Next steps, in order of value

### 1. Fix the research exit ladder — do this first, it needs no further study

`src/lib/trading/engine.ts:49-51`

```ts
const RESEARCH_ATR_SL_MULT = 1.5;
const RESEARCH_ATR_TP_MULT = 1.2;   // <- 1.2 / 1.5 = 0.8:1 reward:risk
const RESEARCH_MIN_RISK_REWARD = 0.5;
```

Every `research-N` strategy trades this live. In the weekly in-sample sweep,
`single 1.2 ATR` was the **worst of all 20 variants** (avgR +0.037 vs baseline
+0.076) despite the **highest** win rate (57.7%) — break-even at 0.8:1 is a
~55.6% win rate, so it clears the bar by 2 points and earns half the expectancy.
research-29 ran it live at 43.8%.

`single 2.5 ATR` measured +0.089 in-sample on the same table. But note it FAILED
out-of-sample as a *pick* (−0.021 wk, +0.002 d), so do not swap 1.2 → 2.5 and
call it validated — the defensible claim is only "0.8:1 is measurably bad", which
is enough to justify moving off it.

Read the comment block above those constants before editing: it explains that the
tight ladder exists deliberately, to make live paper trading match whatever the
research loop backtested. Changing the constant without changing what the
research loop backtests against just re-introduces the mismatch in the other
direction. **The real fix is probably to make the research loop backtest and
report its own exit geometry per strategy, not to retune a global constant.**

### 2. Re-run the sweep with risk-normalised lots

`scripts/exit-geometry-sweep.mts` passes `lot = 1` for every trade, so the PF
column is a dollar ratio dominated by high-priced, high-ATR names. On daily IS it
contradicts totalR outright (PF 0.97 against totalR +399). The live desk sizes to
constant dollar risk (`computeLot`: `riskUsd / slDistance`), under which summing R
*is* summing dollars — so totalR is the honest column and PF is currently noise.
Making the sweep size the same way would let both columns be quoted.

### 3. Only then consider turning trailing stops on

`trail 1.5/1.5` passed the full protocol (pre-registered, OOS-confirmed, held at
3x sample and on a second timeframe, positive in 10/10 weekly years including
both bear years, with a pre-registered control that failed). On weekly — the
desk's timeframe — it is **+0.021 avgR and ~36% more trades**. Real, small.

Remaining reasons not to ship it yet: idealised stop fills (gaps through a stop
are not modelled, and a trail exits at a stop far more often than the ladder
does), and survivorship bias in `.cache/bars/sp500-1d.json` (today's index
membership projected backwards). Neither invalidates the comparison — the
baseline makes the same assumptions — but both flatter the absolute numbers.

Note `1.0/1.5` performs nearly as well, which is *good* news: it means the
1.5/1.5 cell is not a tuned spike. Do not present 1.5/1.5 as an optimum.
